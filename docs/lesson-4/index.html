生存三分钟

怪物贴身时，血条告诉你还剩多少机会；击败怪物后，选择一次成长。每次只改一小处，先预测，再运行，最后解释为什么。

开始前：只读眼前需要的文件

起始课包与评分已提供。本课有六项任务、13个定位标记；01–05自动评分，06单数值实验由老师人工验收。学生起点保留待实现部分，能编译运行不代表已经完成；声音试听与自然三分钟试玩仍要现场检查。

从老师公开库的 lesson-4 分支取得课包。已有自己的复刻和upstream时，先保存当前课的改动、用 git status 确认状态，再按 Git手册的取课流程 新建自己的练习分支：

git fetch upstream
git switch -c my-lesson-4 --no-track upstream/lesson-4

已建过my-lesson-4就不再用 -c，先查看自己的分支再继续。origin是你的复刻，upstream是老师库；只在自己的练习分支修改，不覆盖上一课。只想先离线读课包，可在lesson-4分支页面点Code → Download ZIP并解压，自动提交评测仍按Git手册走复刻流程；不要用main分支的ZIP代替本课起点。

取课后先启动一次。在 MSYS2 UCRT64 的课包目录执行：

能打开窗口只是能启动的未完成起点，不代表六项任务已完成。关闭窗口后，直接到 01定位血条函数，先画固定100像素的绿色条；现在不用执行其他命令或通读字段。

02 · 保护、闪烁与受伤声

src/game.cpp → TakeContactDamage() → TODO(L4-02-B)

本项 player.invulnerability 和参数dt都是float秒数；只减计时，不给仍按帧的移动速度乘dt。

先带着问题读三处已有语句：main中 float dt = GetFrameTime(); UpdateGame(dt); 取得这一帧秒数并传下去；game.cpp的UpdateGame中 UpdateProtection(dt) 每正常帧只调用一次，随后才 UpdateEnemies(dt)；UpdateEnemies只看 if (CheckCollisionRecs(enemies[i].rect, player.rect)) 内的 TakeContactDamage();，即每只活动怪确认碰撞后才调用。传dt、循环怪物和碰撞调用都已给，不在TODO里再写一遍。

先手推0.8减0.3得0.5，再减0.6得负数，所以需要夹到0。把「剩余值减本帧秒数，再写回」落成一条局部赋值 player.invulnerability = player.invulnerability - dt;，随后自己补小于0的处理；不要只计算临时结果却忘记写回。接触函数先读保护：受保护便提前return；通过后再组织扣血夹零→立即写保护/播放受伤声→判断致死状态。下面两怪实验中，第一只把共享保护从0写成0.8，第二次调用读的就是这个新值，因此在你写的提前退出处停止，不再扣血；不是每怪各有一份玩家保护。

  1. 先做倒计时：player.invulnerability 减dt一次，最低0；公共初态后先一次设 player.invulnerability=0.8f;，再依次调用 UpdateProtection(0.3f)、UpdateProtection(0.6f)，预期约0.5→0。
  2. 再做有效接触：未保护才扣10HP，最低0，立即设置 INVUL_SECONDS=0.8f 并调用现成 PlayHurtSound()。血量归零立刻设Lost；保护中不扣、不响。接触怪物仍活着。
  3. 最后只控制图像：无保护始终可见；保护时用 static_cast<int>(player.invulnerability * 10) % 2，结果为0显示、1隐藏。PlayerVisible 返回bool；G身体框仍显示，碰撞身体不消失。

只往公共初态接这两只合法普通怪，先预测首帧90还是80，再观察HP和闪烁：

enemies[0] = {player.rect, EnemyKind::Grunt, 1, true};
enemies[1] = {player.rect, EnemyKind::Grunt, 1, true};

首次接触应90，两怪都还在；约0.8秒后仍接触才再伤。02组核对次数，现场试听受伤声一次；子弹命中仍是 PlayHitSound，别混用。短调用实验里 TakeContactDamage() 表示一次已经确认的接触事件，它本身不搜索怪物。计时helper可直接单测；暂停由整帧入口管理，不给每个helper重复加状态门。

再读返回值怎样接到画面：PlayerVisible起点只有固定 return true;；DrawGame已有 if (PlayerVisible()) DrawSprite(SpriteId::Player, player.rect);。true才画角色，false只跳过这一行，身体数据和碰撞不动。可以在这个TODO内暂把固定返回改成 return false;，运行看图像消失，再恢复；这不是最终规则。最终用「无保护返回true；有保护返回余数是否等于0的比较结果」两条路径替换固定返回，保留前面的秒数乘10取整数再模2公式：余数0→比较为true→绘制，余数1→比较为false→跳过绘制。不要直接返回 % 2 的整数结果，因为0转false、非0转true，会把显示规则反过来。不要在判断前留一个永远先执行的return，否则后面的逻辑走不到。

闪烁可先不用怪物：公共初态设保护0.35秒，第一次可见判断的整数段是3、余数1，返回false，图像隐藏；换成0.25秒，整数段2、余数0，返回true，图像显示。自然帧会继续减保护，所以观察的是一段交替过程，不是要求某个小数永久停住。两怪实验先查HP，再查图像，最后试听，一次只排一个问题。

为什么一帧两怪也只伤一次？

第一只有效接触立即写入保护，第二只读到新值便跳过。若等循环结束才保护，两只会各扣10。计时只在整帧入口减一次，不能每遇到一怪减一次。

survivalTime 是float秒数。战斗模式才累计 survivalTime 秒，封顶 SURVIVAL_SECONDS=180；仍Playing且战斗到时才Won，不能覆盖Lost。练习不生存计时、不自然刷怪，但人工怪物、接触和XP测试有效。死亡在02完成，结算画面由 DrawResult 提供，显示时间、kills、level和score。

读末尾门的先后：UpdateEnemies(dt) 可能写Lost，紧接的 if (gameState == GameState::Lost) return; 已拦住致死帧；之后是 HandleHits(); CheckWin();，最后只有Playing才 BeginUpgrade()。这些调用与门由老师提供，不重复添加。由此推导本项职责：UpdateSurvival判断战斗并更新秒数；CheckWin核状态、模式与时间，只负责成立时写Won；不能把任何到时状态都改成Won。先圈条件再写更新，把死亡优先留在现有顺序中。

不用先等三分钟：公共初态接 practiceMode=false; survivalTime=179.99f; UpdateGame(0.02f);，无怪应Won且时间180。另一次加 player.hp=10; 和02的第一只重叠怪，再调这一帧，应Lost而非Won。然后用练习初态只调 UpdateGame(181.0f)，时间仍0。自然帧恢复后再演示三分钟。

GameEnded() 由老师提供，仅Won或Lost返回true；ChoosingUpgrade不是结束。因此main传给音乐的是这个bool，选择时音乐继续，终局才暂停。不要把「不是Playing」直接当结束，否则选成长时就误停音乐。相机与绘制仍被main调用，这是继续展示冻结的一局，不是继续推进模拟。

终局等待数据不变。Enter全重置但保留当前模式/调试；TAB切模式并全重置；G仅视觉。检查HP100、经验0、等级1、攻击1、间隔0.3、保护/冷却/计时/kills/score=0、旧弹怪清空、候选重置、镜头回出生点；音乐随重开恢复。跑03组。

这里先分清三种数字：命中是子弹确实扣到怪物HP；击败是怪物HP降到零后退出活动；score是按种类给的分数。只有后两者中的击败数量决定固定经验。读死亡分支时圈出调用，不把奖励挪到循环外；循环外既不知道这次是否死亡，也可能一次处理多只。奖励函数不用再扣怪物HP。

upgradeChoices 是三项UpgradeKind数组。先验证状态是ChoosingUpgrade且index在0..2，不成立就退出；验证通过后才读取 upgradeChoices[index]，否则可能越界。给每种效果自行列「读哪些字段、写哪些字段、哪里夹上限」，再用已学的switch/分支组织，效果应用完才回Playing。不要把索引误当选项类型，随机后「1」不总是攻击。

  • FireRate：player.shotInterval 乘0.8，最低 MIN_SHOT_INTERVAL=0.12 秒。

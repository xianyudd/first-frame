第 4 课 · 血条 → 受伤反馈 → 胜负 → 重开

生存三分钟

上一课让大地图、镜头、墙和声音一起工作。这次让玩家能看清血量，受伤后获得短暂保护，撑满三分钟获胜。先做小改动，再自己安排更新流程。

开始前：准备与代码

当前是学习说明，不是已交付课包。第 4 课起始代码、定位标记、受伤音效与自动评测尚未提供。现在可以读代码、纸上推演；收到老师确认的课包后再实现，保留第 3 课备份。

先确认 L3 镜头跟随、挡墙和子弹命中正常。收到课包后打开 src/main.cpp，用函数名查找位置。

先找文件末尾的 int main()：while前的 InitGame()是开局；循环内每轮是按键 → 玩家/子弹 → 刷怪 SpawnEnemies、接触 UpdateEnemies、命中 HandleHits → 镜头/音乐 → DrawGame。Enter、TAB 重开才再调用 InitGame。

文件上方的同一个 player和子弹、怪物数组供各函数共享：初始化重置，更新修改，绘制只读来画，不用各建一份数据。

拟新增数据：在 Player内声明 int maxHp = 100;（用 player.maxHp访问）和 float invulnerableTime = 0.0f;（无敌剩余秒数）。

在文件上方 Player player、score等全局数据旁、ConfigOf定义之前声明全局 float elapsedTime = 0.0f;（生存秒数）、int killCount = 0;（击败数）、const float SURVIVAL_SECONDS = 180.0f;（目标秒数）。小数计时用 float，不用 int；状态在 04 引入。

变量 lowerCamelCase，函数 PascalCase，常量 UPPER_SNAKE_CASE；四空格缩进，必要注释用简短中文。

01 · 最大血量与血条

要做什么
在固定 HUD 中画血条，初始血量与最大血量都是 100，血量减少时填充变短。
先知道什么
比例＝当前血量÷最大血量。整数 50 / 100得到 0，要先做浮点除法：static_cast<float>(player.hp) / player.maxHp。最大血量必须大于 0；DrawGame只把局部显示比例夹紧在 0..1，不修改 player.hp，伤害处理处负责让 HP 最低为 0。满条取 200 像素，则 100/100、50/100、0/100 分别填 200、100、0 像素，最后用 static_cast<int>转成整数宽度。
改哪里
怎么推进
  1. 扩充 Player；检查 InitGame里的旧花括号初始化。新增字段后，优先逐字段赋值，不猜聚合初始化的字段顺序。
  2. 设置 player.maxHp = 100，再用它设置当前血量；重开也应恢复。
  3. 在 DrawGame找到 EndMode2D()，往下看旧 HUD 背景与文字。血条放在这些绘制之后、原 if (gameOver)结算分支之前，仍在 EndDrawing()之前。用 DrawRectangle(x, y, width, height, color)先画底条再画填充，另用 DrawText显示血量；位置不挡旧文字。先画固定 200 像素条，确认看得见，再接比例测 50/0 血。后画的背景会盖住先画的条。
验证
临时分别设 100、50、0 血，核对 200、100、0 像素；再试负血量应显示空条而非反向条。走远后血条仍固定在屏幕；撤掉临时设值，Enter 恢复 100/100。
额外排错：半血却空了？

先单独算除法，再算像素。若得到 0，检查转换是否发生在除法之前；绘制位置正确但宽度错，先别改相机。

02 · 受伤后 0.8 秒无敌

要做什么
有效接触扣 10 血后，立即保护玩家 0.8 秒。L4 接触不再让怪物消失，也不算击败。
先知道什么
无敌时间用秒，不用帧数。在 main的 while内、按键处理之后，每帧只调用一次 GetFrameTime()，保存为 float dt。倒计时减 dt，低于 0 就设为 0；本课不改角色、子弹和怪物的原速度单位。
改哪里
怎么推进
  1. InitGame把 player.invulnerableTime设为 0。
  2. 在现有 if (!gameOver)花括号内、UpdatePlayer()之前只减一次倒计时。本项先保留旧条件，04 再换成 Playing；无需改 UpdateEnemies签名。若自建计时函数，才传 dt 并同步声明、定义和调用。
  3. 在 UpdateEnemies找到接触分支：重叠且无敌时间为 0 才扣血，血量最低为 0；扣血后立即把无敌时间设为 0.8f。后面的怪物就会看到保护已经生效。
  4. 删除接触导致怪物失活的旧行为，保留怪物追击与墙判断；不要改子弹命中的失活规则。
验证
在 main中 while前那次 InitGame()之后，仅一次设 HP=100、player.invulnerableTime=0.0f，放两只 rect=player.rect、active=true的怪物；按已有 Enemy声明补合法 kind 和 hp。设置不放进 while；测试不按移动键、Enter 或 TAB：首帧后 HP=90，不是 80，两怪仍活动。纸上再算 0.8−0.3≈0.5、再减 0.6 归零，这不是自然帧 dt；实测保护期间仍 90，归零后接触变 80。撤掉临时设置。
额外提示：为什么不能最后才设无敌？

按数组顺序画两个怪物的判断过程。若等循环结束才设保护，第二只怪物读到的仍是 0，就会再次扣血。

停止点一 · 血量与保护

先展示满/半/空血条，解释浮点除法；再推演同帧两怪接触和保护归零。确认后再做反馈，不要同时改全部流程。

03 · 闪烁与受伤声

要做什么
保护期间让玩家图像闪烁；玩家每次真正扣血时发出一次受伤声，而不是接触每帧都响。
先知道什么
闪烁只控制绘制，不删除身体、取消碰撞或改怪物的 active。可把剩余秒数分成 0.1 秒小段：static_cast<int>(player.invulnerableTime / 0.1f) % 2，余数交替为 0/1；不在保护期则始终画玩家。
改哪里
怎么推进
在 DrawGame只给玩家的 DrawSprite加绘制条件，G 身体框仍可显示。受伤声的调用时机放在 UpdateEnemies有效扣血事件里，与进入保护相邻。现有 src/audio.h只有 PlayShotSound()和 PlayHitSound()；后者是子弹命中怪物声，不是玩家受伤声。独立受伤资源与约定接口由老师后续提供；现在不写一个不存在的函数调用。先定位事件，接口到齐再接声音。
验证
一次接触让 HP 100→90，约 0.8 秒内交替可见，之后稳定可见；按 G，消失的图像仍对应同一身体框。当前只验证闪烁和扣血事件时机；资源交付后再试听：这次受伤响一次，保护期间重复接触零次，子弹命中怪物仍用原命中声。
额外排错：为什么一直隐身？

查保护结束后是否无条件恢复玩家绘制；不要让“闪烁的某一半周期”成为平时唯一的绘制条件。

04 · 三分钟胜负

要做什么
HP 归零失败；战斗模式活着撑满 180 秒胜利。练习模式不累计生存时间、不判到时胜利，仍可移动、射击、更新保护和人工测试接触；两种模式都可能因血量归零失败。结束停止战斗和计时。
先知道什么
enum class GameState { Playing, Won, Lost };定义状态类型，GameState::Playing/Won/Lost对应进行中/胜利/失败。在枚举之后、各函数之前声明全局 GameState gameState = GameState::Playing;，供各函数共享，替代所有旧 gameOver判断。只有 Playing 且 !practiceMode才加 dt 累计生存时间，累计值封顶；显示剩余时间用 SURVIVAL_SECONDS - elapsedTime，最低为 0。
改哪里
怎么推进

A · 先接失败状态。在本 src/main.cpp搜索 gameOver，联动检查：

  • 旧全局声明换为上面的枚举和状态；InitGame旧重置改为 Playing。
  • UpdateEnemies有效扣血且 HP 归零的位置，立即设 Lost 并 return;，停止整个函数，后续怪物不再移动；break只退出当前循环，不能代替它。
  • DrawGame旧结算条件改为非 Playing；main旧更新条件改为 Playing，音乐实参用下面的 bool 桥接。

找到 main含 UpdateEnemies(); HandleHits();的旧行，拆开两次调用；前者返回后，只有 Playing 才执行 HandleHits。这一组改齐再编译，不是删掉旧声明就停。先完成下面的 A 验收。

B · 再接战斗计时。InitGame重置时间为 0。Playing 内仍更新保护、玩家、子弹、刷怪与接触；仅 !practiceMode在接触前累计时间。接触后仍 Playing 且是战斗模式，才判到时 Won，失败优先。练习由原刷怪函数跳过刷怪，不能把运动一起关掉。按键、镜头、音乐与 DrawGame留在战斗条件外；结束不再更新战斗或计时。

验证
  1. A：沿 02 的 while前入口，初始化后仅一次设 HP=10、保护=0，放一只合法活动怪物与玩家重叠；不按键。接触应 Lost，等待时战斗冻结；再按 Enter 应 Playing、HP=100、旧怪物清空。
  2. B：临时把 SURVIVAL_SECONDS改成 10 秒。练习模式重开后等超过 10 秒：仍 Playing，elapsedTime=0。TAB 切战斗并重开，存活到 10 秒应 Won、剩余 0；再等 2 秒数据不变。
  3. 同帧死亡：设 practiceMode=false，调用 InitGame得到 Playing 并清空旧对象；更新前仅一次设 HP=10、保护=0、elapsedTime=9.99f，放一只合法活动怪物，其 rect=player.rect；其余怪物/子弹保持空，不按键。仅这一帧用 0.02 替代 dt：UpdateEnemies返回后应 Lost，不是 Won。撤掉测试设置，恢复 180 秒并验收战斗模式三分钟。

现有音乐接口是 UpdateGameAudio(bool gameOver)，不改 audio.h的参数名。传入“状态不是 Playing”的比较结果，例如 gameState != GameState::Playing，不能把 enum 直接传给 bool 参数。结束暂停音乐，重开后比较结果变 false，原接口负责恢复。

额外排错：为何结束后还在计数？

逐项检查战斗函数的调用条件。状态改变以后，不只下一帧要停，本帧剩下的战斗更新也要停。

05 · 击败数结算与 Enter 重开

要做什么
结束页区分胜利/失败，显示生存秒数、击败数和 Enter 重开说明；每局数据独立。
先知道什么
击败数不是得分，也不是命中次数。一次怪物从活动变为死亡失活才加 1；一只重甲挨三枪仍只算一只。接触不失活、不增加 killCount，已经失活的怪物不再参与命中。
改哪里
怎么推进
  1. 在 HandleHits已有“血量≤0 → 失活 → 加分”的死亡分支给 killCount加 1，不改变加分规则。
  2. 在 InitGame的 score清零旁重置 killCount。先验收计数和重开，再补文字。其他新增数据也在这里重置，保留原清空对象与镜头初始化。
  3. DrawGame读计数，在 04 改好的结算分支内补胜负、生存时间、击败数及已有 score得分文字，用屏幕坐标；重开得分归零。

Enter、TAB 原本已调用 InitGame，无需重写按键逻辑，检查这两条路径都能重置。重开保留当前模式，G 仍只切视觉调试；音乐沿用 04 的 bool 桥接。

验证
一只 3 血重甲：前两枪 killCount=0，第三枪=1，之后空枪仍=1；再击败普通怪变 2。结束后按 Enter：HP=100、保护=0、时间=0、killCount=0、Playing，旧弹怪消失、镜头回出生点、音乐恢复。再按 TAB，模式确实切换且同样重置；按 G 不改变这些数值。
额外排错：重开还在结算？

分别查结算的状态条件和 InitGame 的状态重置；别只清文字。再检查是否仍有旧 gameOver 判断挡住更新。

06 · 自己设计一个边界实验

要做什么
选一个最容易被写错的规则，自己给出输入、预期和理由，再验证。
先知道什么
预期要由规则推出，不能照当前输出倒填。例如无敌刚好归零、同帧多怪、结束后一颗弹本来会击杀怪物、重开残留保护，都可成为测试题。
改哪里
怎么推进
自己选择相关的初始化或函数入口，用最少的临时改动安排场景；先写 HP、秒数、活动对象和状态，再画这一帧调用顺序。使用纸上推演加受控手测，完成后撤掉临时改动。
验证
交一条“输入 → 预期 HP/时间/killCount/状态 → 实际 → 理由”的记录。指出它能抓住哪种错误；若不同，缩小场景后再判断是实现还是预期错。

课后：补主线，再从 A/B 选一

A · 血量显示实验：比较最大血量 100 和 150 的两组比例，自己选一个非整数像素结果，先算再画。只改变血条尺寸或文字布局，不改伤害规则；解释转成整数后的差异。

B · 胜负与重开实验：自行设计两条操作序列，其中一条包含“结束 → TAB → Enter”，逐步预测模式、状态、时间和击败数，再实测。保留 180 秒主线版本，短时实验完成后恢复常量。

第 4 课 · 血量 → 胜负 → 经验 → 三选一成长

生存三分钟

怪物贴身时，血条告诉你还剩多少机会；击败怪物后，选择一次成长。每次只改一小处，先预测，再运行，最后解释为什么。

开始前：只读眼前需要的文件

起始课包与评分已提供。本课有六项任务、13个定位标记；01–05自动评分，06单数值实验由老师人工验收。学生起点保留待实现部分，能编译运行不代表已经完成；声音试听与自然三分钟试玩仍要现场检查。

从老师公开库的 lesson-4 分支取得课包。已有自己的复刻和upstream时，先保存当前课的改动、用 git status 确认状态，再按 Git手册的取课流程 新建自己的练习分支：

git fetch upstream
git switch -c my-lesson-4 --no-track upstream/lesson-4

已建过my-lesson-4就不再用 -c，先查看自己的分支再继续。origin是你的复刻，upstream是老师库；只在自己的练习分支修改，不覆盖上一课。只想先离线读课包，可在lesson-4分支页面点Code → Download ZIP并解压，自动提交评测仍按Git手册走复刻流程；不要用main分支的ZIP代替本课起点。

最短路先看 29 行的 src/main.cpp。开窗口、加载资源、InitGame()；循环读按键和一份 GetFrameTime() → UpdateGame(dt) → 镜头、音乐、绘制；退出释放资源。今天不改这条主线。

接着在 src/game.h 只找当前任务的数据和函数声明。extern Player player; 是「同一份数据的名字」，不新建玩家；src/game.cpp 唯一定义数据并处理规则；src/drawing.cpp 只读数据画画。地图、镜头、对象池、assets.h 与 audio.h 由老师提供，不必通读。

Player 的 rect 是身体，speed 是每帧移动量；hp/maxHp/attack/xp/level 是整数；invulnerability、shotInterval 是浮点秒数。Bullet 有 rect/vx/vy/active/damage；Enemy 有 rect/kind/hp/active。其中rect是 Rectangle，speed/vx/vy是float，active是bool，damage和怪物hp是int。全局 survivalTime/shotCooldown 是float秒数，kills 是int；upgradeChoices 是三项UpgradeKind数组。弹怪仍按帧移动，只有计时使用秒，别给旧速度再乘 dt。

InitGame 已给初态：HP/maxHP=100/100、attack=1、shotInterval=0.3 秒、level=1、xp=0、保护和冷却=0；survivalTime、kills、score=0，弹怪全空。GameState 有 Playing/ChoosingUpgrade/Won/Lost 四种值，用 GameState::Playing 写出类型所属的值。

make todo
make run
make test
make test VERBOSE=1

在 MSYS2 UCRT64 的课包目录执行。make todo 列出下面13个真实标记；复制标记到指定文件 Ctrl+F，不靠固定行号。01–05有自动检查：起点尚未实现应红，默认看英文失败明细与组摘要，VERBOSE=1 详细模式列每条PASS/FAIL，失败含定位与预期/实际。课包应有 tests/test_todos.cpp、tests/test_support.h 和 tests/fake.cpp；若缺文件，确认取得的是完整lesson-4起点，不删目标假通过；06不算自动成绩。

受控实验放哪里、怎样撤销？

先备份；仅在 main 开头那次 InitGame(); 之后、while 之前插入一个临时块，不放进循环。每次从以下完整初态开始，再接本任务的小片段。只测试一个场景，不按移动/射击/Enter/TAB，除非实验要求；做完删除整个临时块，重新编译，Enter核对恢复。实验调用不是函数答案。

{
    practiceMode = true;
    debugMode = false;
    InitGame();
    // 这里只接一个任务的实验片段。
}

这会保留合法出生位置、100血、Playing、零经验/计时和空弹怪。若要战斗场景，在片段里明确改 practiceMode=false；InitGame 保留模式。读完本项再打开此处，不用先理解初始化内部。

每项的读法相同：先看目标和标记，再读helper旁边几行，找到「输入什么、修改什么、返回什么」。声明末尾的分号只告诉你能怎样调用；带花括号的定义才执行工作。不要在头文件再定义一份player，也不用新建类。留白里的 (void)dt 或 (void)index 只是避免未使用参数警告，写逻辑时可移除。

本页说「看01组」是运行同一个 make test 后找01的结果，不是另有分组make目标。组编号对应 TODO_STATUS；详细模式便于定位第一条失败。局部检查与整帧检查都要读，后者可能同时依赖多项尚未完成的任务，不能因为别组仍红就把刚写的局部函数全部推倒。

01 · 画会缩短的血条

src/drawing.cpp → DrawHealthBar → TODO(L4-01)

老师已画灰底 DrawRectangle(16, 66, 200, 16, GRAY)。你补同位置、同高度的绿色前景：DrawRectangle(x, y, width, height, GREEN)，宽度取整数像素。先试固定宽100，确认出现，再接血量比例。

整数 50/100 为0；局部比例可写 static_cast<float>(player.hp) / player.maxHp。分母≤0时比例取0，否则把比例夹在0..1，宽度是200乘比例后转 int。绘制不修改HP，也不用改老师提供的 InitGame。

卡住时，只做下一小步

先纸上写「血量 → 比例 → 像素」三列，再在函数里保存局部比例。把小于零、大于一的情况分别处理，最后才转换像素。比如25/100应是0.25、50像素；1/3乘200约66.67，转成整数是66，不四舍五入。若颜色盖住文字，先核对调用位置；这个函数已在HUD背景之后调用，不要搬到世界绘制里面。

先算再看：公共初态后只设 player.hp=50;，应半条100像素；再分别试100、0、负数与超过maxHp，应该满/空/空/满，maxHp=0也应安全空条。每次只改这个实验值。走远后HUD仍固定；若半血空了，先查除法，别改镜头。跑01组，再撤销临时设置。

  1. 先做倒计时：player.invulnerability 减dt一次，最低0；公共初态后先一次设 player.invulnerability=0.8f;，再依次调用 UpdateProtection(0.3f)、UpdateProtection(0.6f)，预期约0.5→0。
  2. 再做有效接触：未保护才扣10HP，最低0，立即设置 INVUL_SECONDS=0.8f 并调用现成 PlayHurtSound()。血量归零立刻设Lost；保护中不扣、不响。接触怪物仍活着。
  3. 最后只控制图像：无保护始终可见；保护时用 static_cast<int>(player.invulnerability * 10) % 2，结果为0显示、1隐藏。PlayerVisible 返回bool；G身体框仍显示，碰撞身体不消失。

只往公共初态接这两只合法普通怪，先预测首帧90还是80，再观察HP和闪烁：

enemies[0] = {player.rect, EnemyKind::Grunt, 1, true};
enemies[1] = {player.rect, EnemyKind::Grunt, 1, true};

首次接触应90，两怪都还在；约0.8秒后仍接触才再伤。02组核对次数，现场试听受伤声一次；子弹命中仍是 PlayHitSound，别混用。短调用实验里 TakeContactDamage() 表示一次已经确认的接触事件，它本身不搜索怪物。计时helper可直接单测；暂停由整帧入口管理，不给每个helper重复加状态门。

闪烁可先不用怪物：公共初态设保护0.35秒，第一次可见判断的整数段是3；换成0.25秒，段是2，图像状态应相反。自然帧会继续减保护，所以观察的是一段交替过程，不是要求某个小数永久停住。两怪实验先查HP，再查图像，最后试听，一次只排一个问题。

为什么一帧两怪也只伤一次？

第一只有效接触立即写入保护，第二只读到新值便跳过。若等循环结束才保护，两只会各扣10。计时只在整帧入口减一次，不能每遇到一怪减一次。

03 · 撑满三分钟，结算这一局

src/game.cpp → UpdateSurvival(float dt) → TODO(L4-03-A)

src/game.cpp → CheckWin() → TODO(L4-03-B)

战斗模式才累计 survivalTime 秒，封顶 SURVIVAL_SECONDS=180；仍Playing且战斗到时才Won，不能覆盖Lost。练习不生存计时、不自然刷怪，但人工怪物、接触和XP测试有效。死亡在02完成，结算画面由 DrawResult 提供，显示时间、kills、level和score。

只读 game.cpp 末尾 UpdateGame(float dt)：它是真暂停/终局的整帧入口。Lost/Won整帧返回；正常帧计时→运动/射击→接触，死亡立即停止；之后命中→胜利→升级。负dt先夹0。测试整帧必须调用它，不能直接调低层函数后声称「暂停失效」。

不用先等三分钟：公共初态接 practiceMode=false; survivalTime=179.99f; UpdateGame(0.02f);，无怪应Won且时间180。另一次加 player.hp=10; 和02的第一只重叠怪，再调这一帧，应Lost而非Won。然后用练习初态只调 UpdateGame(181.0f)，时间仍0。自然帧恢复后再演示三分钟。

GameEnded() 由老师提供，仅Won或Lost返回true；ChoosingUpgrade不是结束。因此main传给音乐的是这个bool，选择时音乐继续，终局才暂停。不要把「不是Playing」直接当结束，否则选成长时就误停音乐。相机与绘制仍被main调用，这是继续展示冻结的一局，不是继续推进模拟。

终局等待数据不变。Enter全重置但保留当前模式/调试；TAB切模式并全重置；G仅视觉。检查HP100、经验0、等级1、攻击1、间隔0.3、保护/冷却/计时/kills/score=0、旧弹怪清空、候选重置、镜头回出生点；音乐随重开恢复。跑03组。

src/game.cpp → BeginUpgrade() → TODO(L4-04-B)

先只读 HandleHits 的死亡小分支：实际击败才调用 RewardKill。每只 kills+1、player.xp+10；kind不改变经验，原score仍按配置算。三血重甲前两次命中没有击败，第三次才给经验，接触也不给。

ExperienceNeeded() 老师已提供，固定返回100。你先在 BeginUpgrade 检查Playing、level<6、xp≥100，成立才扣100并升一级，保留余量；这里只做04那一处，抽取和暂停留给05。等级初始1，最多6，满级继续攒XP但不弹。

这里先分清三种数字：命中是子弹确实扣到怪物HP；击败是怪物HP降到零后退出活动；score是按种类给的分数。只有后两者中的击败数量决定固定经验。读死亡分支时圈出调用，不把奖励挪到循环外；循环外既不知道这次是否死亡，也可能一次处理多只。奖励函数不用再扣怪物HP。

预测表自己填：xp=99/100/235、level=1，调用一次 BeginUpgrade() 后应分别为99/1、0/2、135/2（XP/等级）。公共初态改一个xp值再调；04尚无暂停时不放任多帧运行，用04组看单次结果。满级6、xp100应不扣不升。实际击败再用战斗验证；别为了变绿给「每次命中」加奖励。

05 · 三选一：分三次停下来

第一小段 · 先出现选择，再恢复

UpgradeKind 四值是 Attack/FireRate/MaxHp/Heal。老师的 FillUpgradeChoices(UpgradeKind out[3]) 已从四种打乱取三个不同值；04升级成立之后，你调用它填写 upgradeChoices，进入ChoosingUpgrade。面板和1/2/3按键老师已接好，传入 ApplyUpgrade 的index是0/1/2。

这一小段先只做合法选择与恢复，不急着填四种效果：只接受ChoosingUpgrade中的0..2，完成一次便回Playing，非法索引或其他状态不改数据。公共初态接 player.xp=100; BeginUpgrade();：面板出现、等级2、xp0。先等、按W和箭头，生存/保护/冷却、角色/弹/怪、刷怪都冻结；UI与音乐继续。按一个数字后下一帧才恢复运动。停下来演示暂停和恢复，再往下写。

想看见「倒计时也暂停」，怎样给初态？

在公共初态之后、触发升级之前，再设保护0.5秒、冷却0.2秒，并放一颗待飞行旧弹和一只远处普通怪。空地图附近的合法位置如下；这些都是测试对象，不是让你改刷怪逻辑。

player.invulnerability = 0.5f;
shotCooldown = 0.2f;
bullets[0] = {{700, 400, 10, 10}, 9, 0, true, 1};
enemies[0] = {{900, 400, 40, 40}, EnemyKind::Grunt, 1, true};
player.xp = 100;
BeginUpgrade();

选择时怪的位置、保护闪烁阶段都应固定。选择后下一帧，旧弹飞行、怪重新追来、闪烁阶段继续变化；保护和冷却不能在你犹豫时耗光。先只做恢复时四种效果还没写，数值不增长是这一停止点允许的暂态，05自动全绿要等三段都完成。

第二小段 · 一次只写一种效果

读取 upgradeChoices[index]，用已学的switch/分支完成下列规则，再测试下一种。不要把索引误当选项类型，随机后「1」不总是攻击。

  • Attack：player.attack 加1。
  • FireRate：player.shotInterval 乘0.8，最低 MIN_SHOT_INTERVAL=0.12 秒。
  • MaxHp：maxHp加20，hp也加20并夹上限，保留缺血量；70/100变90/120。
  • Heal：hp加30夹到maxHp；90/100变100/100，不加上限。

公共初态后设 player.hp=70; gameState=GameState::ChoosingUpgrade; upgradeChoices[0]=UpgradeKind::MaxHp; ApplyUpgrade(0);，应90/120与Playing。替换选项/血量逐个预测；再调一次不应再加。测试xp235：第一次选择后余135，选择那帧始终返回，下一帧才再扣100、升一级、弹下一次，不能一键连选；满级不再弹。停下来解释两种回血的区别与余量。

第三小段 · 射速要能体验，旧弹不追溯

src/game.cpp → FireBullets() → TODO(L4-05-C)

src/game.cpp → FireBullets() → TODO(L4-05-D)

只看该函数两处：冷却>0时不能新发射；成功找到空槽才把 player.attack 记到 bullet.damage，把 shotCooldown 设为当前间隔。池满不设冷却、不响。老师已在UpdateGame每帧减冷却夹0；按住箭头发射，方向优先Right>Left>Up>Down，每次一颗、不斜射。

快照的理由先用纸上时间线解释：发出旧弹时攻击1，选择界面暂停，攻击升到2，恢复后旧弹命中；它携带的damage仍是1。若命中时再读取player.attack，就会把旧弹也变强。间隔表示「两次成功发射之间等多久」，数值越小才越快；射速提升不改变子弹飞行速度。

先按住右键比较0.3与一次FireRate后的0.24秒；再试多次降到0.12不再降低。攻击实验：让一颗damage=1的旧弹存在，再升级attack到2，新弹damage=2，旧弹仍1。用05详细检查验证满池与快照，不必手打128颗。第三次停下来讲「出生时记下」和「随时读取」的区别，再跑完整01–05。

06 · 只改一个数，预测再实测

src/my_experiment.h → myExperiment → TODO(L4-06)

先保留主线版本。挑一个成长数值，例如FireRate倍率或Heal量，只改变那一个数，不改多个效果、输入或tests。自己选合法初态、调用/操作和可观测结果，写下预测再运行；一次结果不同就缩小实验，不照结果倒填预测。

例如你选择回血量，先自行给当前/最大HP，说明离上限还有多少，再算增加后的数；另一个初态可选接近上限。你要说明看见的变化来自改动的那个数，还是原本夹上限的规则。记录不一致也有价值：把其他输入保持不变，再查这次选择究竟是哪一种，别同时改血量上限和回血量。

ExperimentNotes 字段依次是 recorded（bool）、change/prediction/observation/explanation（const char* 文本）。在现有 myExperiment 花括号里填改动位置与前后值、初态及预测、实测、解释；有记录才设true。HUD只提示老师审核，不会自动判06通过。展示基线与实验的差异，实验后恢复主线数值并复测。

课后：补主线，再二选一

A · 成长数值实验：接06，保留只改一个数的版本，自己选第二个初态检查上限或边界。带预测、实测和解释，不追加新系统。

B · 操作序列：设计两条序列，其中一条含「选择 → Enter → TAB → G」。逐步预测模式、状态、HP、XP、等级与计时，再运行核对。未完成主线先补；不用修改固定tests换绿。

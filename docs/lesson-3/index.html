我的竞技场

上一课用种类和配置表，让怪物有了不同的速度、血量和贴图。这一课继续改这个游戏：先像改配置一样扩大地图、摆一块新墙，再让镜头跟随玩家，最后补上挡墙和声音。仍然写一点、跑一次，看看画面怎样变化。十项可以分几次完成。

开始前：找到任务

先取回本课起始代码，再创建练习分支

本课起始代码：lesson-3 分支。在你自己的复刻仓库目录中，先保存旧课的修改，再取回老师提供的起始代码：

git fetch upstream
 git branch -r --list upstream/lesson-3

看到 upstream/lesson-3 才继续；如果没有看到，先向老师确认分支是否取回，不要用main或旧课代码代替本课起点。

git switch -c my-lesson-3 --no-track upstream/lesson-3
make todo
make run
make test

已有 my-lesson-3 则用 git switch my-lesson-3 返回，别重复创建。保存一项后，检查 git diff，只提交自己改的学生文件；首次备份用 git push -u origin my-lesson-3。不要合并旧课整份 main.cpp 覆盖新起点；需要时仅迁移自己已完成的配置表。复刻需启用 Actions，详见 进度与提交。

三步找到当前任务

十项任务共有十二个唯一定位标记：01 与 07 各有 A/B 两处；其余各一处。

  1. 打开 src/main.cpp，看文件开头的任务目录；第10项在 src/my_cases.h。
  2. 在这份课包的MSYS2 UCRT64终端运行 make todo，查看每个标记所在的文件和行号。代码修改后行号可能变化，用标记查找更方便。
  3. 从下面任务复制唯一 TODO(L3-xx...) 标记，回到指定文件按Ctrl+F。先读标记前后的代码，弄清输入和用途，再修改这项任务对应的部分。提示只帮助你迈出下一步，具体实现由你完成。
make todo
make run
make test

在课包根目录（有Makefile的那一层）运行。起始代码可以编译；测试会指出哪些任务还没有完成。先关注当前任务对应的结果，保留tests中的原测试，用它们检查自己的实现。WASD移动，方向键射击，G看格线/身体框，ENTER重开，TAB切练习/战斗，Escape退出。

图片和声音资源已准备好，程序也已经安排了声音的加载、更新和释放，以及镜头初始化、玩家移动后的镜头更新调用。扩地图、镜头函数内容和绘制分层仍由你实现。这次只需要决定声音在什么事件发生时播放，不需要修改声音的加载、更新和释放。加载只在准备阶段进行，不要每帧重新加载。

写一点，运行一次

  1. 先看现象：运行游戏，看看本项要改变什么；再对照现有代码和下面的说明。
  2. 试一小步：先改一个数值或试一个局部例子，不必一次写完整个函数。
  3. 先预测：运行前想一想画面或数值会怎样变化。
  4. 动手改：找到本项标记，完成对应改动。
  5. 检查：make test看对应组，make run观察实际效果。
  6. 说清原因：比较预测与实际，用自己的话说明为什么。

下面会直接说明动手需要的概念，不用先通读手册。卡住时逐级打开提示；想确认某个字段或函数的用途，再查对应资料。

可选参考：在MSYS2安装目录的 ucrt64/include/raylib.h 搜索 Camera2D、BeginMode2D、EndMode2D、CheckCollisionRecs。需要确认字段或参数时，再查对应说明。可主动打开 raylib官方cheatsheet查函数签名，也就是函数名、参数和返回类型；学习内容可离线阅读；在线时字体与 GitHub 自动进度可能发起请求。

世界坐标与屏幕坐标

世界坐标：描述墙和角色在整张地图中的位置。屏幕坐标：描述画面上的点在窗口中的像素位置。这里的镜头（相机）由Camera2D表示，决定把哪一块世界画到窗口中；它不改变角色和墙在世界中的位置。

地图行列 × TILE → 世界宽高
世界中的玩家中心 → camera.target
窗口中的屏幕中心 → camera.offset
zoom = 1，rotation = 0

例如，镜头可以把世界点(1800,900)画在屏幕中心(640,360)，角色的世界坐标仍然是原来的值，不需要减掉1280。碰撞检查始终比较世界中的矩形。本课主线让玩家一直居中，不做平滑跟随，也不限制镜头在世界边缘的位置：走到边缘时，窗口会显示一部分地图外的空白。先观察并解释这个现象，选做C再研究怎样让镜头停在边缘。当前用方向键射击；以后做鼠标瞄准时，再研究把屏幕坐标转成世界坐标的GetScreenToWorld2D。
